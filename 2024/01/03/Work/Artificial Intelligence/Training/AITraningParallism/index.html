数据并行 DP

(Data Parallelism)

  • 思想：把同一个模型放在多个GPU上，batch数据平均分布到各个GPU上，并行计算。
  • 难点：注意参数同步和信息过期问题。
  • 优点：
    • 加速比线性。
    • 部署简单工作量小，每个节点内的计算效率高。
    • 由于部署简单，是最先采用的并行方式。
  • 缺点：
    • 需要在每个节点复制所有模型参数，显存重复度高，利用率低，并不适合大模型的部署。只适用于训练样本较多而模型较小的情况。
    • 数据分布在不同机器，需要allreduce同步权重 FS（fully shared）DP

特点+具体操作：

  • 同构模型，不同数据：每个节点都包含完整的模型，以及模型的参数（weight，parameter），输入数据则根据模型的并行度进行拆分，分别被每个节点读取；
    • 假设我们有8张GPU卡或者昇腾的NPU卡来训练图片分类的模型，训练的批量为160，那么每张卡上面分到的批量数据（min-batch）为20，每张卡基于样本数据完成训练。
  • 独立运行：每个节点读取相应的输入数据后，分别独自处理模型的前向和反向传播，并得到Gradients，归并所有的梯度并更新梯度；
  • 梯度聚合：因为各张卡上处理的数据样本不同，所以获得的梯度会有些差别。因此，需要对梯度进行聚合（求和、均值）等计算来保持和单卡训练相同的结果，最后再更新参数。
  • 统一通讯：所有节点之间的通信，主要包括前向传播的Loss归并以及反向传播的gradient归并以及更新，这些通信则是通过相应的通信原语（gather/reduce/broadcast）操作。
  • 参数更新：梯度聚合会让各卡的模型以相同的梯度值同时进入参数更新阶段，然后针对新的数据进行下一轮训练。

模型切分的共同背景

模型并行把模型或计算图拆到多个设备，适用于单卡放不下完整模型的情况。它需要人为设计切分边界并支付通信成本；张量并行、流水线并行与专家并行只是不同切法，不需要再用一个空泛的“模型并行”标题把它们强行包在一起。

张量并行 TP

Tensor Parallelism 是模型并行的一种

  • 思想：通过在多个计算设备上分片模型参数来实现并行。
  • 举例：一个操作中进行并行计算，主要是矩阵-矩阵乘法。张量并行训练是将一个张量沿特定维度分成 N 块，每个设备只持有整个张量的 1/N，同时不影响计算图的正确性。这需要额外的通信来确保结果的正确性。
  • 底层逻辑是矩阵乘法的拆分计算, 矩阵乘法中列并行与行并行这两种张量并行的方式，以及它们在前向传播和反向传播中的区别。^14
  • 难点：额外的通信
  • 优点：每个设备只持有整个张量的 1/N

序列并行 SP

Sequence Parallelism 不是一种单独算法

SP 只说明输入或激活沿序列维切分，没有说明 Attention 如何取得其他分片的上下文。真正决定显存、通信、头数限制和迁移成本的是 Attention 内部选择 AllGather、All-to-All、P2P Ring，还是它们的二维组合。

两条技术路线

同一个名称下实际有两条不同路线：

  1. TP 配套的 Megatron SP：只把 LayerNorm、Dropout 等逐 token 激活沿序列维切开，Attention 和 MLP 仍由 TP 负责。它的目标是消除 TP 区域之间的冗余激活，不能单独解决长上下文 Attention。[^8]
  2. 长上下文 SP/CP：网络输入和各层激活始终保持 N/P 的序列分片；Attention 再通过 AllGather、All-to-All 或 Ring 取得全局上下文。Ulysses、Ring Attention、Megatron Context Parallelism（CP）和 USP 都属于这条路线。

三个容易混淆的名称

  • Megatron SP 是 TP 配套的激活优化。
  • Megatron CP 是贯穿所有层的长上下文切分，Attention 默认以 Ring 交换 KV。
  • USP 在原论文中指 Unified Sequence Parallelism，即 Ulysses × Ring 的二维组合；部分框架也把 Ulysses Sequence Parallel 简写成 USP，阅读配置时需要回到具体通信原语。

反向、重计算与卸载

前向只要沿箭头走一遍，确实比较直观；反向最容易产生的误解是：“PyTorch 有 autograd，所以 Ring 梯度通信和 FPDT 的分块调度也是系统自动推导出来的。” 实际上，autograd 更像一个按依赖倒序叫号的调度员，它不会凭空发明分布式算法：

  • 普通 PyTorch 算子已经登记了梯度公式，模型作者调用 loss.backward() 后，autograd 自动串起这些公式。
  • 自定义分布式算子必须由框架作者手写 backward()：包括梯度张量如何切分、该做 All-to-All 还是 Ring、累加发生在哪个 rank，以及返回给上游的布局。autograd 只负责在恰当时机调用它。[^41]
  • activation checkpoint 必须显式圈定要重算的函数或层。反向到达这个边界后，checkpoint 包装器恢复输入和随机数状态、重新执行一次前向，再让 autograd 对新图求导；系统不会自行猜测最合适的重算边界。[^42]
  • activation offload 必须显式决定保存什么、搬到哪里、何时预取。通用 save_on_cpu 或 saved-tensor hook 可以自动执行登记好的 pack/unpack，但 FPDT 还有自己的 pinned buffer、CUDA stream 和预取次序。[^43]

先分清三种内存策略

假设一段前向为 Y=f(X)，反向需要 X、中间激活 A 和上游梯度 dY。三种方案解决的是同一显存问题，但付出的代价不同：

  1. 普通保存：前向把 A 留在 GPU，反向直接读取。速度最快，HBM 占用最高。
  2. 重计算：前向只保留边界 X；反向先重新执行 f(X) 得到 A，再计算梯度。省 HBM，增加一次前向计算；若 f 内含 A2A/Ring，通信也会重放。
  3. 卸载：前向把 A 搬到 CPU，反向再预取回来。它不重新计算 A，但增加 D2H/H2D、pinned RAM 和同步成本。
  4. 重计算 + 卸载：checkpoint 的边界输入可以在 CPU；反向先 H2D 取回 X，再重跑 f(X)，最后执行自定义 backward。FPDT 还可能在这次重跑的前向里，再次建立自己的 Q/K/V/O/LSE CPU 状态。

卸载不是重计算

从 CPU 取回旧值叫 reload，从输入重新算出新值才叫 recompute。 两者可以同时存在。只看显存曲线时它们都像“激活消失后又回来”，但性能瓶颈分别是 PCIe 带宽与额外 FLOPs/通信，调优方式完全不同。

Ring Self-Attention

方案一：先环传 K 算分数，再环传 V 算输出。

  • 起因：2021 年的方案面对的是最直接的长序列问题：若每张卡都保存完整 Q/K/V 和 S×S 分数矩阵，显存很快耗尽；只做 TP 又没有切掉序列长度。
  • 小白直觉：每张卡把自己的 Q 留在原地，让其他卡的 K 依次“排队来做题”；所有题目的分数归一化后，再让 V 按相同顺序走一圈，累加出本地 Q 的输出。
  • 关键对象：本地 Q_i/K_i/V_i 为 [B,S/P,H,D]；每轮分数块 score_ij 为 [B,H,S/P,S/P]；O_i 为 [B,S/P,H,D]。与现代 Ring Attention 不同，早期方案要先得到并保存分数块，再开始 V 阶段。

效果与局限：它证明了“Q 留在本地、K/V 环传”可以突破单卡序列上限，但两阶段通信和分数块存储并不理想。今天更常见的 Ring Attention 用 blockwise/FlashAttention 与 online softmax 边算边归并，通常不再照搬这份实现。

Megatron SP

方案二：只切 TP 外围的逐 token 激活。

  • 起因：Megatron 的 TP 已经切分了 Attention/MLP 权重，但 LayerNorm、Dropout 和残差仍会在每个 TP rank 保存同一份完整序列激活，浪费显存。
  • 小白直觉：像多人合写一本书。真正需要多人共同计算的 Attention/MLP 前，把各自页码临时拼成整本；算完马上把结果按页码散回去。Norm、Dropout、残差只看单个 token，所以各人处理自己的页即可。
  • 关键边界：本地 X_i/N_i/Y_i 是 [S/P,B,M]；进入 TP 区域前 AllGather 成 [S,B,M]；TP 线性层生成的部分和再由 ReduceScatter 归并为 [S/P,B,M]。它减少激活复制，没有让 Attention 获得超长上下文的能力。

实现与迁移：Megatron 当前在 TP Linear 的映射函数中实现这对通信，固定代码版本可见 layers.py 的相关路径。[^25] 在 MCore 内接入通常只是配置；迁移到新框架时，需要同时处理 TP Linear 边界、Dropout RNG 和残差布局，否则代码看似能跑，数值语义却可能改变。

DeepSpeed-Ulysses

方案三：用 All-to-All 在序列维和头维之间换轴。

  • 起因：Ring 的多轮 P2P 代码复杂，且小块通信可能难以吃满高带宽网络。Ulysses 希望只在 Attention 前后各做一次集合通信，中间仍调用普通的本地 Attention kernel。
  • 小白直觉：开始时每人拿“所有题型的一小段题目”；交换后，每人改成拿“少数题型的全部题目”。这样每个人都能独立完成自己那些 Attention heads，再把答案换回原来的序列分片。
  • 布局变化：输入 Q_i 是 [B,S/P,Hq,D]；All-to-All 同时在序列维 gather、头维 scatter，得到 [B,S,Hq/P,D]。K/V 同理变成 [B,S,Hkv/P,D]；输出再逆变换回 [B,S/P,Hq,D]。

实现与局限：DeepSpeed 把输入校验、两次 All-to-All 和本地 Attention 封装在 DistributedAttention 中。[^26] 纯 Ulysses 的并行度不能超过可切分头数；MHA 通常看 Q heads，GQA 的 K/V 布局常把约束收紧到 KV heads，MQA 只有一个 KV head 时尤其棘手。packed sequence、cross-attention 或 TP 同时切头时，还要重新核对维度映射。

Ring Attention

方案四：KV 边走，Attention 边算，softmax 在线合并。

  • 起因：早期 Ring Self-Attention 要先存分数、再传 V；Ulysses 又受头数整除限制。Ring Attention 希望每张卡始终只保存本地 Q 和一个 KV block，并把通信隐藏在块计算之后。
  • 小白直觉：本地 Q 是考生，KV block 是依次经过考场的题本。每来一本就立即算这一部分答案，并保存“当前最大分数、归一化总和、加权输出”三个统计量；题本走完一圈，局部答案就等价于看过完整上下文。
  • 关键对象：Q_i 为 [B,S/P,Hq,D]，当前 KV_j 为 [B,S/P,Hkv,D]；块 Attention 返回 O_ij 与 LSE_ij，online merge 把它们稳定地合并为 O_i/LSE_i，无需物化完整 S×S 分数矩阵。

实现与局限：官方 JAX 实现把通信 stream、块 Attention 和 online merge 放在同一循环中。[^27] 它不切 head，因此没有 Ulysses 的头数上限；但实现明显更难，因果 mask 的负载均衡、通信与计算是否真能重叠、反向传播的块调度，都会影响结果。块太小或跨节点网络太慢时，“通信免费”并不成立。

Megatron CP

方案五：把 Ring Attention 变成框架能力。

  • 起因：论文级 Ring 算法还不等于生产训练。框架需要让每一层都保持序列分片，同时兼容 TP/PP/DP、RoPE、因果负载均衡、GQA/MQA、Flash/Fused kernel 和 checkpoint。
  • 小白直觉：Megatron 负责“分组、切序列、摆好数据”，Transformer Engine（TE）负责“边收 KV 边算 Attention”。用户通常只选 CP 度和通信后端，不必在模型层手写 Ring 循环。
  • 与 Megatron SP 的差别：CP 让输入、Norm、Attention 输出、MLP 和残差都保持 [S/P,B,M]；只有 Attention 为取得全局上下文而跨 CP rank 通信。Megatron SP 则会在 TP Attention/MLP 前临时恢复完整序列。

实现与迁移：当前 MCore 配置把 p2p 明确标为可异步并与 Attention 重叠，并在 TE wrapper 传入 CP group、global ranks、stream 和通信类型。[^28] 在支持的 GPT/LLaMA 路径中迁移成本低；若新模型改变 Attention 语义，例如特殊稀疏 mask、cross-attention 或自定义状态空间模块，仍需后端真正理解 CP，而不是只加一个配置开关。

USP

方案六：用二维进程网格组合 Ulysses 与 Ring。

  • 起因：纯 Ulysses 集合通信效率高，却受 head 数约束；纯 Ring 不受 head 限制，却可能在节点内浪费 NVLink 集合通信能力，并在大 P 下产生很多 P2P 轮次。
  • 小白直觉：先在“同一排”用 Ulysses 快速换轴，再在“同一列”用 Ring 扩展上下文。假设总并行度 P=P_u×P_r，只有 P_u 消耗可切分 heads，P_r 可以继续增大。
  • 布局变化：初始是 [B,S/(P_uP_r),H,D]；Ulysses A2A 后是 [B,S/P_r,H/P_u,D]；Ring 在 P_r 组中流动 KV；最后逆 A2A 回到原序列分片。

反向与重计算

USP 的反向不是把前向图“左右翻转”这么简单，而是遵守链式法则的后进先出。前向是：

Q/K/V 局部序列 → A2A₁（序列换头）→ Ring Attention → A2A₂（头换序列）→ O_i。

因此反向依次为：

  1. 先穿过 A2A₂：本地序列布局的 dO_i 通过 A2A 变成 head-sharded 的 dO_u=[B,S/P_r,H/P_u,D]。
  2. 再做 Ring backward：固定本地 Q_u 和 dO_u，让 K/V block 走一圈；与此同时，属于各个 KV owner 的 dK/dV 部分梯度也沿 Ring 流动并累加。
  3. 最后穿过 A2A₁：head-sharded 的 dQ_u/dK_u/dV_u 通过逆布局 A2A，回到每个 rank 原始的局部序列分片。
  4. 普通投影层接管：本地 QKV Linear 的 autograd 根据 dQ_i/dK_i/dV_i 继续得到 dX_i 与参数梯度。

Ring backward 需要前向的 Q/K/V、最终输出 O 和 log-sum-exp LSE。LSE 是 online softmax 的归一化账本：没有它，就无法把每一个 KV block 的局部梯度还原到同一个全局 softmax。YunChang 的 RingFlashAttnFunc 正是在 forward context 中保存这些对象，并在自定义 backward() 中调用手写的 Ring FlashAttention backward。[^44]

上面把通信写成便于理解的同步形式；高性能实现会把下一轮 K/V 与 dK/dV 的收发提前挂到通信 stream，并与当前 block backward 重叠。关键不变：**dQ 对所有可见 KV block 的贡献在 Q owner 本地相加；dK/dV 对所有 Q block 的贡献必须回到 KV owner 后才完整。** 源码因此同时维护 K/V 通信器和梯度 K/V 通信器，而不是依赖一次普通 all_reduce。[^44]

实现支持要看具体 backend

“USP 算法存在反向”不等于每个 kernel 分支都支持训练。YunChang 当前实现的 A2A 与 Ring FlashAttention 路径各自注册了 custom backward；但官方 README 仍标注部分 Torch efficient attention 分支没有 backward。接入新 NPU、稀疏 Attention 或自定义 mask 时，必须逐 backend 检查并做分布式数值对齐，不能只看 forward 能跑。[^19][^44]

实现与局限：YunChang 先创建 Ulysses/Ring 两套 process group，LongContextAttention 再顺序执行 A2A、Ring Attention、逆 A2A。[^29] 它缓解但没有消除 head 限制：P_u 仍必须与 Q/KV heads 兼容。二维 group、TP group 和物理拓扑一旦映射错误，通信会跨越慢链路，代码也比单一方案更难读。

AllGather CP

方案七：先复制完整 KV，再调用标准 Attention。

  • 起因：不是每一种新 Attention kernel 都立刻有 Ring 版本。工程上需要一个最简单、最接近单卡语义的 CP 后端，用于先验证正确性或快速接入特殊 Attention。
  • 小白直觉：Q 仍各管各的序列片段，但开考前每个人都复印一套完整 K/V。之后直接调用普通 Attention；反向时再把各人对 K/V 的梯度贡献相加并散回原 owner。
  • 关键对象：Q_i/K_i/V_i 是 [B,S/P,Hq|Hkv,D]；AllGather 后每张卡临时拥有 K_full/V_full=[B,S,Hkv,D]；输出仍是本地 O_i=[B,S/P,Hq,D]。

为什么这里没有论文原图

AllGather CP 不是一篇独立论文提出的新 Attention 算法，而是 MCore 的 CP 通信后端。 因此这里不伪造“论文图”，证据应回到 TransformerConfig.cp_comm_type：当前源码明确说明 all_gather 是同步路径，不能与 Attention 计算重叠；同一枚举还列出 p2p、a2a 与 a2a+p2p。[^21][^28]

效果与局限：它不切 head，MHA/GQA/MQA 都能复用标准 kernel，代码最容易读，迁移成本也最低。但完整 KV 的峰值显存会随 S 增长，且当前 MCore 路径不能异步重叠，因此更适合 CP 度较小、正确性基线、Ring kernel 尚未适配或特殊 Attention 快速接入，不适合作为超长序列的大规模默认方案。Python 配置值是 cp_comm_type="all_gather"，部分命令行枚举写作 allgather。

Ulysses-Offload / FPDT

方案八：把一次完整 Ulysses Attention 变成 CPU—GPU 流水线。

  • 起因：普通 Ulysses 把每卡输入切到 S/P，但 A2A 换轴后，一个 rank 仍要一次处理“完整 S、部分 heads”的 Q/K/V。序列变到百万 token 后，Attention 的 Q/K/V、反向保存状态、FFN 和 logits 工作区仍会造成峰值。FPDT（Fully Pipelined Distributed Transformer）因此不再把一个 rank 的局部序列当成一整块处理，而是在 Ulysses 内部继续分块。[^37][^38]
  • 小白直觉：普通 Ulysses 像把一本巨著按“章节”分给多个人；FPDT 又把每个人的章节切成小页包。GPU 桌面上只放当前页包和下一包，其他页包存在 CPU 仓库；GPU 计算当前包时，后台同时搬下一包，尽量把 PCIe 搬运藏在 Attention 计算后面。
  • 关键对象：C 是配置的全局 Attention chunk 长度，u=S/C。每卡本地 X_i=[B,S/P,M] 会被切成 u 份 [B,C/P,M]；QKV 投影并 A2A 后，当前 rank 得到 [B,C,H/P,D]。这个 C/P → C 的换轴是读懂源码和估显存的关键。[^39]

FPDT 让工作集由可调的 C 决定，因此显存不必一次容纳完整 Attention，可以把可训练长度继续推高；它不是说任意整数长度都无需处理。当前 DeepSpeed 实现要求 S 能被 P 与 C 整除，通常由 DataLoader pad 到共同倍数；它依赖 FlashAttention，当前自定义路径只支持无显式 attention_mask 的因果 Attention，并继承 Ulysses 的 head 切分约束。Megatron-DeepSpeed 集成还标注了 FPDT dropout 限制。[^39][^40]

反向与卸载

FPDT 不能依赖 autograd 把一个巨大的标准 Attention 图原样反传，因为那会重新把所有 Q/K/V、中间输出和 workspace 同时拉回 GPU，抵消 offload 的意义。因此 DeepSpeed 把 Attention 整体实现成 torch.autograd.Function：前向在 no_grad 下执行并建立自己的 SequenceChunk 状态表；反向则由源码显式控制每一个 chunk 的 H2D、FlashAttention backward、累加、D2H 和 A2A。[^46]

与 checkpoint 叠加

Megatron-DeepSpeed 的 FPDT 示例同时打开 activation checkpoint、checkpoint-in-cpu 与 FPDT offload。它们嵌套后的实际时序是：[^45][^47]

  1. 第一次前向：外层 checkpoint 在 no_grad 下运行 FPDT，只保存 Transformer block 的边界输入，并可把它搬到 CPU；因为内部输入不要求梯度，这一次 FPDT 不保留供长期反向使用的完整自定义 context。
  2. 到达 checkpoint 反向：从 CPU 取回 block 输入，恢复 model-parallel RNG，在 enable_grad 下重跑整段 FPDT 前向。Ulysses A2A、chunk Attention 与 online merge 都会再次执行。
  3. 建立新 FPDT context：这次重跑会创建真正供反向使用的 Q/K/V/O/LSE SequenceChunk，并按 FPDT 规则卸载到 CPU。
  4. 执行 FPDT custom backward：autograd 调用上面的手写分块反向，逐块预取状态、算梯度、逆 A2A，并返回 dX/dW/db。
  5. 越过 checkpoint 边界：checkpoint wrapper 把重算输入的 .grad 交还给更早的层。

这套组合用更多前向 FLOPs、额外 A2A 和 PCIe 流量换更低 HBM。FPDT 把 SequenceChunk 等对象直接挂在 custom Function context 并自行管理，不能假设 PyTorch 的通用 saved_tensors_hooks 会自动接管这些私有对象；迁移到新框架时必须保留或重新实现它们的生命周期。[^43][^46]

显存为什么不是常数：以每卡峰值做量级估算，FPDT 的序列相关部分可写成

M_peak_gpu ≈ M_model + κ0·b·B·S·M/P + κ1·b·B·C·M/P + M_buffer/workspace，

而 host 保存量约为 M_peak_cpu ∝ L·b·B·S·M/P。固定 C 只约束 chunk-local Q/K/V、双缓冲和 kernel 工作区；每卡当前层的本地 hidden state 等基座仍随 S/P 增长。因此 GPU 总峰值不与 S 完全无关，也不与 P 严格成反比；模型状态、通信 buffer、allocator 和某些复制对象会形成下限。

效果与局限：论文报告在相同硬件上最长序列最高提升 16×，8B 模型在 4 GPU 上训练 2M token 且 MFU 超过 55%；更大的 70B/4M 配置使用 32 GPU。它的代价是高额 pinned CPU RAM、PCIe/NUMA 敏感性、三条 stream 和自定义 autograd 带来的复杂度。C 太大容易 OOM，太小又使 kernel 变碎、通信更难隐藏，所以必须按模型、硬件和 S 实测峰值与 MFU。[^37][^38]

FSDP2 迁移

FSDP2 负责参数/梯度分片，FPDT 负责 activation 的 chunk/offload，理论上互补，但当前 Ulysses-Offload 是 Megatron-DeepSpeed 的定制执行路径，不是可直接套到 FSDP2 的开关。建议分四步迁移：

  1. 先拆清 group 所有权：FSDP2 mesh 只负责参数 AllGather 与梯度 ReduceScatter；独立 sp_group 负责 FPDT 的 Ulysses A2A。两者可以包含同一批 rank，但 collective 的语义、顺序和 stream 不可混用。
  2. 把 FPDT Attention 做成显式模块边界：模块接收 sp_group、C 和 pinned-buffer 管理器，不读取 DeepSpeed 全局状态；先只移植 Attention chunk/offload，FFN 与 loss 保持普通实现，得到可对齐的最小版本。
  3. 审计参数生命周期：若自定义 backward 或重计算需要再次读取投影权重，必须确保 FSDP2 已在相应 pre-backward 阶段 unshard；按 Transformer block 自底向上 fully_shard，并验证 reshard_after_forward 不会让自定义 autograd 持有失效参数视图。FPDT activation offload 与 FSDP2 参数/梯度 CPU offload 是两套机制，不应共用 buffer 或含混统计。
  4. 最后恢复完整流水线：所有 rank 必须进入相同数量、相同顺序的 A2A 与参数 collective；再逐步加入双缓冲、tiled FFN/loss、变长 padding、checkpoint 和 torch.compile。验收应从 SP=1 数值基线、SP=2 固定长度开始，随后覆盖非整除长度、GQA/MQA、gradient accumulation、保存恢复，并分别记录 GPU 峰值、CPU 峰值和 PCIe 暴露时间。

FPDT 的 custom Function 把投影权重作为输入，并在 backward() 返回 dW/db；FSDP2 必须在这段 backward 运行前让对应参数处于可读的 unsharded 状态，并在梯度出现后仍能触发自己的 ReduceScatter/post-backward 生命周期。若为了 checkpoint 在反向中重跑 FPDT forward，参数还会被再次读取一次。因此移植时不能只验证最终 loss，还要给每个参数注册临时 hook，确认梯度只完成一次、shape 与 shard 一致、FSDP2 ReduceScatter 没有早于 custom backward。

这条迁移路线复用的是 FPDT 的对象生命周期与调度思想，不是复制 DeepSpeed 私有 autograd。它比 ALST 的 HF Ulysses wrapper 更难移植；在 FSDP2 上没有公开同条件基准前，应把它视为待验证工程设计，而非现成功能或性能承诺。

ALST

方案九：Ulysses 之后，继续处理 MLP、logits 与 checkpoint activation。

  • 起因：旧版 DeepSpeed-Ulysses 主要把长序列分摊给多个 rank，并在 Attention 前后完成序列维与头维的换轴。序列继续变长后，即使每张卡只保留 S/P_s 个 token，[B,S/P_s,M] 的 MLP 中间量、[B,S/P_s,V] 的 logits、逐层保存的 checkpoint activation 和内存碎片仍会依次成为 OOM 来源。DeepSpeed 当前旧教程也已经把读者指向新的 ALST 集成。[^30][^31]
  • 小白直觉：Ulysses 是把一条很长的流水线分给多张卡；ALST 又规定每张卡不要一次加工完自己手中的全部 token，而是把逐 token 工序切成小段，并把暂时不用的 checkpoint 搬到 CPU。它是一套建立在 Ulysses 上的长序列内存工具箱，不是新的 Attention 通信原语。
  • 四个主要部件：HF Ulysses 在 SP rank 间分摊 Attention activation；Tiled Loss 避免物化完整 logits；Tiled MLP 只保留一个序列 Tile 的工作区；activation checkpoint offload 把跨层保存的 hidden states 移到 CPU。Liger fused loss 和 expandable_segments allocator 是额外的高收益实现选择。[^32]

这里的任意长度不是无限长度

seq_length_is_variable=True 的含义是：UlyssesSPAttentionHF.forward() 每次从当前 Q 的局部长度重新计算 local_seq_length 与 global_seq_length，因此不同 batch 不必共享一个固定 S。它仍有四个边界：

  1. 长度整除：当前 UlyssesSPDataLoaderAdapter 会检查 S mod P_s == 0，不满足就报错。框架可在进入 adapter 前 pad 到 S'=ceil(S/P_s)P_s，并把补位 label 设为 -100；verl 已有这种 pad-and-slice 实现。[^33][^36]
  2. Head 约束：Hq mod P_s == 0；KV heads 还要满足 Hkv mod P_s == 0 或 P_s mod Hkv == 0，后一种情况通过复制 KV heads 支持 GQA/MQA。最大 SP 度仍不超过 Q heads。
  3. 资源上限：Tiling 把某个逐 token 算子的峰值工作区从“全序列”降到“单 Tile”，但不会让总显存、CPU RAM 或通信缓冲无限大。
  4. 计算上限：dense Attention 的时间仍是 O(S²)。论文的 15M token 配置一次迭代约 7 小时 25 分，说明“能跑”与“高吞吐”是两个目标。[^32]

为什么 label 必须先移位：自回归训练用位置 t 预测 t+1。若先把序列切给多个 rank，再让每个 rank 独立 shift，除最后一片外，每个分片末尾都会丢掉下一个 rank 的首 token 目标。ALST 因此先在完整样本上生成 shift_labels，再沿序列切分；各 rank 的有效 token 数可能不同，最终 loss 必须按 n_i=(shift_labels_i != -100).sum() 加权，而不能简单平均 rank loss。[^31][^33]

效果应该怎样读：论文在 Llama-8B、H100、ZeRO-3、batch size 1 的特定配置中实现单卡 500K、8 卡 3.7M、32 卡 15M，相对同文 32K baseline 分别是 16×、116×、469× 的最长可运行序列提升。32K 的训练 loss 与 baseline 几乎重合，但论文明确把“可运行的最长序列”放在吞吐之前；CPU offload 还可能把瓶颈转移到主机内存，例如大模型多层 checkpoint 会占用数百 GiB。[^32]

FSDP2 迁移

FSDP2 解决的是参数、梯度和优化器状态分片，ALST 解决的是长序列 activation 与工作区，两者目标互补。现有 verl 已有 FSDP2 + Ulysses 的真实计算路径，证明组合并非概念设想；但这只证明 Ulysses 与 FSDP2 能组合，不能自动推出 DeepSpeed 的 TiledMLP 与 checkpoint offload 已经可直接复用。[^36]

建议按以下顺序实现：

  1. 建立两套逻辑 Mesh：fsdp_mesh 默认可以覆盖 WORLD，用于 fully_shard；另建 [dp,sp] Ulysses mesh，从中取得 sp_group 和数据并行 batch group。若设置较小 fsdp_size，PyTorch/框架可能建立 [ddp,fsdp] HSDP mesh，但它仍独立于 Ulysses 的 [dp,sp] 语义。[^35]
  2. 不要只在 DP 轴 shard 参数：若参数在 SP 轴复制，却没有 HSDP/DDP 等价的 SP 梯度同步，各 SP 副本会更新成不同模型。最简单的 ZeRO-3 对等起点是让 FSDP2 shard group 覆盖所有训练 rank；优化成 HSDP 前先证明梯度归约语义和 loss 缩放正确。
  3. 先移植 Attention 与数据边界：DeepSpeed 的 UlyssesSPAttentionHF 构造器已经接受外部 process_group，但 register_with_transformers() 会自行初始化 DeepSpeed SP group。FSDP2 后端应让注册函数接收 sp_group，在模型实例化前注入 HF Attention wrapper；DataLoader 负责 pad、position_ids、预移位 label 和 SP 分片。
  4. **按层 bottom-up 调用 fully_shard**：FSDP2 在层前 AllGather 参数、层后释放未分片参数，并在反向后 ReduceScatter 梯度。Transformer block 和 root 分层 wrap 才能重叠通信并控制峰值；不要只 wrap root。[^34]
  5. 分阶段移植 Tiling：第一阶段先用 FSDP2 + HF Ulysses + Liger/tiled loss，验证单卡 reference；第二阶段再接 TiledMLP。当前 DeepSpeed TiledMLP.backward 通过 ZeRO 专属 param.ds_grad_is_ready 控制“最后一个 Tile 才归约梯度”，源码也明确留下 DDP/FSDP 需要等价机制的注释，因此不能原样复制。[^33]
  6. 区分两种 CPU offload：FSDP2 CPUOffloadPolicy 卸载参数/梯度，ALST checkpoint offload 卸载 activation；它们是两个独立开关。二者同时开启前要评估 PCIe 带宽、pinned memory、CPU RAM 和 gradient accumulation 的正确性。

FSDP2 迁移的验收顺序

先做 SP=1/FSDP2 与单卡 loss 对齐，再做 SP=2/FSDP2 的固定长度，随后测试不能整除的变长 batch、packed sequence、GQA/MQA、gradient accumulation、checkpoint save/resume。最后才打开 TiledMLP 和两类 CPU offload，并分别记录峰值 GPU/CPU 内存、step time 与通信暴露。目前没有 ALST-on-FSDP2 的论文基准，因此这一段是可验证的工程路线，不是性能承诺。

MindSpeed-MM Chunk Layer

方案十：不增加 SP rank，而是在一个 FSDP2 rank 内把 Decoder Layer 沿序列串行切块。

起因与一句话思路

  • 起因：FSDP2 已经分摊参数、梯度和优化器状态，但一个 rank 仍可能一次性物化整段 [B,S,M] 的 Attention、MoE/MLP 和保存激活。序列增长时，参数能装下不等于这一层的 activation 峰值也能装下。
  • 小白直觉：把一整车货物改成 N_c 趟运输，每趟只加工 C=S/N_c 个 token；为了不破坏因果关系，FA 把前面 token 的 K/V 当作“历史账本”，GDN 把卷积窗口与 recurrent delta state 当作“接力棒”传给下一块。
  • 严格分类：这不是新的 Ulysses、Ring 或 USP 通信后端。调度器看到 ulysses_parallel_size>1 或 ring_attention_size>1 会直接报错，所以它是层内串行分块 + 重计算 + 激活卸载，不是跨 rank 序列并行。它可以运行在采用 FSDP2 的训练栈里，但当前不能与 SP/CP 叠加。[^48]
  • 设计来源边界：第一版源码说明串行 sequence-chunking 语义跟随 XTuner bbd10c1；第二版在 MindSpeed-MM 中重做了 FSDP2 wrapper、FA/GDN cache、D2H 去重和 backward 生命周期。因此更准确的称呼是基于既有串行分块语义的 MindSpeed-MM FSDP2 工程实现，而不是一篇已经发表并完成跨系统评测的新 SP 算法。[^49]

反向、重计算与卸载

训练脚本仍只调用 loss.backward()，但“自动”的含义与 USP/FPDT 一样：autograd 自动按依赖调用已经注册的规则，源码作者仍要手写状态保存、H2D/D2H 时机和特殊算子的 VJP。

这版实现把责任拆成四层：

  1. Chunk 重计算：ChunkDecoder 已被 checkpoint wrapper 包裹。反向到达某个 Chunk 时，框架取回该 Chunk 输入和跨块状态，重跑 Norm、FA/GDN、MoE/MLP，再对新图求导。
  2. saved-tensor pack/unpack：带 _layer_cache_spec 的 K/V 或 GDN state 不走普通逐 tensor offload，而是变成 CacheHandle。前向先把新值放进 layer staging；反向一次 H2D 后，unpack() 用 tensor.set_() 把原 autograd tensor 重新绑定到恢复后的 view。
  3. 层级预取与释放：输出上的 _CacheBackwardEnter.backward() 先恢复当前层 cache，并预取前一层；输入上的 _CacheBackwardExit.backward() 在本层梯度全部通过后释放 device/host cache。
  4. 算子 VJP：FA backend 使用它已注册的 Attention backward；GDN 新增的 stateful causal-conv 是手写 torch.autograd.Function.backward()，显式计算 dx/dw/db/d_initial_state，还把 d_final_state 加回输入窗口。[^49]

Σᵢ 2bBHkv(iC)D = Θ(bBHkvD·S²/C)。

M_FA-D2H ≈ 2bBHkvSD = Θ(S)。

M_GDN-D2H ≈ (N_c-1)b[B·Dconv·W + B·Hv·Dk·Dv]。

显存与“任意长度”的边界

对 full Attention 路径，源码可直接推出一个保守的单卡峰值分解：

M_peak ≳ M_FSDP-model + κ₀bBSM + 2bBHkvSD + κ₁bBCM + M_workspace + M_allocator。

  • κ₀bBSM：层输入和完整 output_buffer；κ₀ 取决于两者生命周期能否重叠释放。
  • 2bBHkvSD：FA 的 K/V staging，或最后一个 Chunk 看到的因果前缀。
  • κbBCM：当前 Chunk 的 Norm、Q、MoE/MLP 和重计算工作区。
  • GDN 不需要增长的 KV 前缀，但 backward boundary cache 约为 (N_c-1) 份 conv/delta state。

所以它的结论不是“峰值与 S 无关”，而是：把一部分原来按整层 S 物化的高系数工作区改成按 C 物化，同时让保存状态的 D2H 去重为线性。 总峰值仍有线性 S 项，也完全没有随 SP size 线性下降的关系，因为当前 P_sp=1。

这里的任意长度不是无限长度

  1. 长度整除：必须满足 S mod N_c = 0；源码没有自动 pad 尾块。
  2. 并行互斥：当前明确拒绝 Ulysses 和 Ring，不能直接与 USP 组合。
  3. Layout 边界：BSND 支持普通 batch；packed TND 仍要求 micro_batch_size=1。
  4. 训练专用：past_key_values 会报错，不能把训练用状态链当成生成 KV cache。
  5. 语义边界：scheduler 丢弃传入的 attention_mask，当前实现围绕因果 FA 和 Qwen3.5 GDN；任意稀疏、滑窗、cross-attention 或自定义 mask 都要重新证明等价性。
  6. Kernel 边界：GDN chunk path 要求 causal-conv 与 GDN 都使用指定 Triton 实现；不是任意 backend 自动获得 state gradient。
  7. 资源与时间边界：pinned CPU、H2D/D2H、完整输出和 FA staging 仍随 S 增长；dense Attention 总计算仍是 O(S²)。

效果应该怎样读：提交 9e9610a4 的标题声称第二版把 D2H 降到 O(n)，源码也能验证“每个新增 K/V token 只进入 staging 一次、最终一次压紧 D2H”的机制；但这个 commit 没有测试文件、峰值曲线、最大序列、吞吐、MFU 或数值对齐结果。本文因此只把它评价为设计上支持把目标长度继续向上扩展的原型。要升级成“任意长度已支持”，至少应补四组证据：与未分块版本的 loss/gradient 对齐、随 S/N_c 的 HBM/CPU/D2H 曲线、FA 与 GDN 的 BSND/TND 矩阵、以及 FSDP2 多卡 step time 与失败边界。

工程联评

下表中的迁移成本与可读性是基于数据布局、通信组、mask/position 处理和 kernel 依赖做出的工程判断，不是论文测量值。显存列统一估算单卡同一时刻的活跃对象：

M_peak = M_model-state + M_saved-activation + max_t(M_operator-workspace(t) + M_comm-buffer(t)) + M_allocator-margin。

其中 b 是每个 activation 元素的字节数，C 是当前方法的 Chunk 长度，N_c=S/C 是层内 Chunk 数，T 是 MLP/loss 的本地 Tile 长度，V 是词表大小，κ 表示实现相关的 Q/K/V 份数、反向保存和 kernel workspace。不能把所有历史 tensor 简单相加，也不能只看渐进式就声称总峰值严格按 S/P 缩放。

选型建议

  1. 先区分目标：只想减少 TP 的冗余激活，使用 Megatron SP；真正被上下文长度卡住，才增加 CP/SP Attention。
  2. Megatron + Transformer Engine 的常规模型：优先从 P2P CP 开始；AllGather CP 用作正确性对照、较小 CP 度或尚未支持 Ring 的 Attention 类型。
  3. 头数充足且通信域带宽高：纯 Ulysses 通常代码更薄、kernel 粒度更大；但需要验证 P_u 能整除 Q/KV heads，并检查 TP 是否也在切头维。
  4. GQA/MQA 或总 SP 度超过 KV head 数：优先 Ring 或 USP；多节点时可把 Ulysses 放在节点内、Ring 放在节点间，再用 profile 选择二维比例。
  5. 不要只看最长序列：固定相同模型与 batch 语义，同时记录峰值显存、吞吐/MFU、通信暴露、因果负载均衡、数值一致性，以及变长/packed sequence 的有效 token 比例。
  6. Ulysses 的 Attention Q/K/V 或反向状态先 OOM：考虑 Ulysses-Offload/FPDT。先 profile 出 C 的可行区间，同时监测 pinned CPU RAM 与 PCIe 暴露；FSDP2 后端应先移植最小 Attention 模块，不要直接照搬 DeepSpeed 私有 autograd。
  7. 已经用 Ulysses 但仍在非 Attention 位置 OOM：再引入 ALST。先启用 tiled/fused loss，再按 profile 决定 TiledMLP 和 checkpoint CPU offload；迁移到 FSDP2 时先完成 Ulysses 与 loss 的正确性闭环，不要一次打开所有内存技巧。
  8. 已经采用 MindSpeed-MM FSDP2，且暂时不需要 SP/CP：可以把 Chunk Layer 作为 Qwen3.5 FA/GDN 的实验性削峰路径。先做 N_c=1 与 N_c>1 的 loss/gradient 对齐，再测 D2H/H2D、HBM 和 CPU RAM；若目标要求 1/P 分摊或多节点扩展，应回到 Ulysses、Ring、USP 或 FPDT，而不是继续增大 N_c。

专家并行 MoE(EP)

MOE的概念

  • 思想：一种基于稀疏 MoE(Mixture-of-Experts) 层的深度学习模型架构被提出，即将大模型拆分成多个小模型(专家，expert)， 每轮迭代根据样本决定激活一部分专家用于计算，
  • 优点：只计算一部分，达到了节省计算资源的效果；
  • 实现：MoE 将模型的某一层扩展为多个具有相同结构的专家网络(expert)，并由门(gate)网络决定激活哪些 expert 用于计算，从而实现超大规模稀疏模型的训练。

MOE 与 EP的关联

[^17]

  • MOE层如果不开EP， MoE的结构由多个 expert 构成，每次只选择一个专家执行；
  • MOE层开启EP，MOE层的多个专家就能同时并行，处理不同的tokens，从而达到并行的效果。为了实现这点需要对topk的token来dispatch和combine

EP 与 TP的区别

  • TP开启时：每个 EP rank 上只包含一部分 expert，而每个 EP rank 上的 token（即 token 对应的 hidden state） 会根据 gating 结果分发到其他 EP rank 上的 expert。这个过程通过 all-to-all 通信完成。
  • 只开启EP时，GPU会拥有多个完整的专家，每个矩阵计算都是完整的，是大矩阵计算。
  • 不同情况各有优劣。

EP、ETP 与 EDP

前面的例子已经出现 ep_tp_world_size 和 ep_dp_world_size，但容易把它们误解为 EP 的两种实现。更准确的关系是：EP、ETP 与 EDP 是 MoE 专家层中的三个正交维度。

维度 全称 对 Expert 做什么 主要通信 单卡专家参数变化
EP Expert Parallelism 把不同 Expert 分到不同 rank token dispatch/combine 的 All-to-All 约按 1/EP 减少本地 Expert 数量
ETP Expert Tensor Parallelism 把一个 Expert 的矩阵切到多个 rank Expert 内部的 AllGather/ReduceScatter 或等价 TP collective 单个 Expert 分片约按 1/ETP 减少
EDP Expert Data Parallelism 复制同一套 Expert 分片，处理不同 token 对应 Expert 参数的梯度归并 不减少单卡参数；增加副本数

ETP：切分单个专家

问题快照：EP 已经减少了每张卡持有的 Expert 数量，但一个 Expert 的 FFN 仍可能过大；它的 W_1/W_2、梯度和 optimizer state 可能无法在单卡驻留。ETP 的物理动作是：让多个 rank 共同保存、计算同一个 Expert 的不同矩阵分片。

效果边界：若全部 Expert 参数、梯度和 optimizer state 为 M_expert_state，只看被 ETP 切分的主项，每 rank 约为：

$$
M_{\text{expert-state,rank}}\approx\frac{M_{\text{expert-state}}}{ETP}.
$$

这里的 M_expert_state 指该 rank 所属 EP 分区中的 Expert model state，不含 Router、共享 Expert、稠密层参数和复制 buffer。总峰值仍应按 model state + saved activation + operator workspace + communication buffer + allocator margin 估算；x_full、partial_y、Grouped GEMM workspace 等不会严格按 1/ETP 下降。因此 ETP 降低的是单 Expert 的模型状态主项，不保证总显存严格反比，也不保证吞吐提高。

适用条件与代价：

  • 适用：单 Expert 放不下，或 Expert FFN 足够宽，切分后每 rank 的 GEMM 仍有足够算术强度。
  • 拓扑：AG/RS 应尽量位于 NVLink/NVSwitch 等高带宽域；跨节点 ETP 往往放大延迟。
  • 性能风险：细粒度 MoE 的单 Expert 本来就小，再提高 ETP 会让 GEMM 更碎、collective 占比更高。Parallel Folding 论文的消融也观察到 ETP 通信开销通常高于 EP。[^52]
  • 迁移成本：新框架需要实现 Expert Linear 的权重分片、前后向 collective、checkpoint reshard、optimizer group 与 token dispatcher 的布局衔接，不能只增加一个整数配置。

EDP：复制专家分片

问题快照：EP 与 ETP 都在切参数，但它们不会自动增加同一 Expert 参数分片处理独立 token 的副本数。当设备数继续增加、模型已经放得下时，需要像普通 DP 一样复制 Expert 参数分片，以扩大 token 吞吐；这就是 EDP。

EDP group 中各 rank 保存相同语义的 Expert 参数分片，但接收不同 batch 或不同序列分片产生的 routed token。反向后，对应 Expert 参数的局部梯度必须在 EDP group 内归并，才能保持副本更新一致。教学图用 AllReduce 表示最基础语义；启用 distributed optimizer 时，实际实现可以使用 ReduceScatter 等分片归并。

对象 代码名 shape 生产者与消费者 生命周期
第 r 个 EDP 副本的 token x_r [T_r,H] dispatcher 产生，Expert copy r 消费 各副本不同的临时激活
Expert 参数副本 w_r shape(W_shard) checkpoint/上次 update 产生，forward/backward 消费 长期参数；各 EDP rank 初始相同

EDP 通常是派生维度，而不是独立切分旋钮。 在不启用 Expert GTP weight rematerialization 时，当前 Megatron 源码按下面的关系生成专家网格：

$$
world_size=ETP\times EP\times EDP\times PP,
$$

所以：

$$
EDP=\frac{world_size}{ETP\times EP\times PP}.
$$

在 Parallel Folding 下，同一个 PP stage 的 rank 数还满足：

$$
TP\times CP\times DP=ETP\times EP\times EDP.
$$

这里普通 DP 属于 Attention/稠密层网格，EDP 属于 MoE 专家网格；二者不必相等。若启用当前实验性的 Expert GTP，还要把对应的 weight-rematerialization 因子计入专家网格，不能继续直接套用上式。[^51]

效果边界：EDP 复制参数，因此不会降低单卡 Expert model state。它主要提高可处理 token/全局 batch 的并行度，代价是 Expert 梯度同步、更多总参数副本和可能更严重的路由负载不均衡。吞吐是否改善取决于每个副本拿到的 token 数、梯度通信是否可重叠、网络拓扑和 global batch 是否足够大。

实现归属与迁移：Megatron DDP 为 Expert 参数选择 expt_dp_group，并按全局 loss 归一化语义调整 Expert 梯度的缩放因子。迁移到新框架时，必须保证相同 Expert shard 被放入同一 EDP group，同时让 Router、共享参数、稠密参数继续使用各自正确的 DP group；把所有参数交给一个普通 DP group 可能造成重复或错误归并。[^53]

Parallel Folding

传统 MoE 布局常把 EP 约束为稠密层 DP 的子组，并让 Expert 层沿用 Attention 的 TP。MoE Parallel Folding 将两套映射解耦：

层类型 独立并行网格 优化重点
Attention / 稠密层 TP × CP × DP × PP 用 TP 放下宽矩阵，用 CP 切长序列，用 DP 扩吞吐
MoE Expert 层 ETP × EP × EDP × PP 优先用 EP 分专家；Expert 太大才提高 ETP；剩余 rank 形成 EDP

配置顺序

  1. 先确定 PP：让单 stage 层数和参数可容纳，并保持 Attention/MoE 的 PP group 一致。
  2. 再确定稠密层 TP/CP：由矩阵大小、序列长度和高带宽域决定。
  3. MoE 优先增加 EP：满足 num_experts % EP = 0，并尽量把 token All-to-All 放在高带宽域。
  4. ETP 从 1 起步：只有单 Expert model state 或 Expert GEMM 尺寸确实需要时再提高。
  5. 由剩余 rank 推导 EDP：检查 EDP 副本是否有足够 token，且 Expert 梯度归并不会成为瓶颈。

最终不要只看 OOM。至少同时记录每 rank Expert 参数/optimizer state、dispatcher buffer、ETP AG/RS buffer、EDP gradient bucket、每个 Expert 的 token 数、Grouped GEMM 尺寸、collective 时间和端到端 MFU；否则只能知道配置能跑，不能知道为什么快或慢。

ZeRO

  • ZeRO通过在多个设备上分片优化器状态、梯度和参数来减少每个设备的存储需求。
  • Zero 优化方法有三个层次，分别是 ZeRO-1、ZeRO-2 和 ZeRO-3。[^13]
  • 它们是由微软提出的 ZeRO（Zero Redundancy Optimizer） 优化技术的不同阶段，旨在减少大规模分布式训练中的内存占用。

1. ZeRO-1：优化器状态分区

  • 目标：减少优化器状态的内存占用。
  • 实现方式：将优化器状态（如动量、梯度方差等）分布在不同的 GPU 上，而不是在每个 GPU 上保存完整的副本。
  • 优点：显著减少内存占用，同时通信开销较小。
  • 适用场景：适合中等规模的模型训练。

2. ZeRO-2：梯度分区

  • 目标：进一步减少梯度存储的内存占用。
  • 实现方式：将梯度分区存储在不同的 GPU 上，每个 GPU 只保存一部分梯度。
  • 优点：内存占用进一步降低，但通信开销有所增加，因为需要在反向传播后聚合梯度。
  • 适用场景：适合大规模模型训练。

3. ZeRO-3：参数分区

  • 目标：最大化内存节省，支持超大规模模型训练。
  • 实现方式：将模型参数分区存储在不同的 GPU 上，每个 GPU 只保存一部分参数。
  • 优点：内存占用大幅降低，可以训练非常大的模型，但通信开销最大，因为需要在每次前向和反向传播时聚合参数。
  • 适用场景：适合超大规模模型训练（如 GPT、BERT 等）。

对比总结

特性 ZeRO-1 ZeRO-2 ZeRO-3
分区对象 优化器状态 梯度 模型参数
内存节省 中等 较大 最大
通信开销 最小 中等 最大
适用场景 中等规模模型 大规模模型 超大规模模型

分层ZeRo

  • 分层Zero（Hierarchical Zero）是一种用于大规模AI模型训练的优化方法，旨在解决传统Zero（Zero Redundancy Optimizer）在大规模分布式训练中的局限性。
  • 它通过分层通信和计算优化，提升训练效率和扩展性。

核心思想是将计算和通信任务分层处理，减少通信开销，提高资源利用率。具体包括：

  1. 分层通信：将通信任务分为多个层次，优先在低层次（如节点内）完成，减少高层次（如跨节点）的通信。
  2. 分层计算：将计算任务分层处理，优先在低层次完成，减少高层次的计算负担。

主要特点

  1. 减少通信开销：通过分层通信，降低跨节点通信频率，提升效率。
  2. 提高资源利用率：分层计算使资源分配更合理，减少闲置。
  3. 增强扩展性：优化后的方法更适合大规模分布式训练，支持更多计算节点。
