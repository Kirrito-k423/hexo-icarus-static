RAM

导言

SRAM 用反馈电路保存状态，DRAM 用电容中的电荷保存状态。 前者访问快，但每 bit 占用面积较大，常用于 CPU 缓存；后者需要刷新，却能以较低成本提供大容量，常用于主内存。

本文先比较两者，再沿着“存储单元 → 内存颗粒与内存条 → 一次读操作”理解 DRAM。只想弄清 SRAM 和 DRAM 区别，读完前两节即可。

RAM 的“随机”是什么意思

RAM（Random Access Memory，随机存取存储器）可以根据地址直接访问目标位置，无须先读完前面的内容。 例如，读取磁带末尾的数据通常需要先走过前面的磁带；访问 RAM 中的某个地址则不需要这种顺序扫描。

“随机”描述的是寻址方式，不意味着没有访问延迟，也不保证每次访问耗时相同。DRAM 是否已经打开目标行、是否正在刷新，都会影响实际延迟。

SRAM 和 DRAM 都是 RAM。这里讨论的普通 SRAM、DRAM 也都是易失性存储器：断电后不能可靠保留数据。

SRAM 与 DRAM 的核心区别

SRAM 是 Static RAM，静态随机存取存储器；DRAM 是 Dynamic RAM，动态随机存取存储器。静态与动态的关键区别是：在持续供电时，是否仍需要周期性刷新来维持数据。

对比表

比较项目 SRAM（静态 RAM） DRAM（动态 RAM）
访问速度 通常更快，适合低延迟访问 通常更慢，访问涉及行激活、感知与恢复等过程
常见容量规模 较小，常用于片上缓存 较大，常用于主内存
单位容量成本 较高 较低
典型用途 CPU 高速缓存、片上缓冲区 计算机主内存，如 DDR 内存条
存储密度 较低；存储相同 bit 数通常占用更多芯片面积 较高；相同芯片面积通常可以容纳更多 bit
单元结构 多个晶体管构成反馈电路，保持两个稳定状态之一 用电容存储电荷，用晶体管控制访问
保存 1 bit 的典型器件数 6 个晶体管（6T） 1 个晶体管 + 1 个电容（1T1C）
电荷泄漏与刷新 存在晶体管漏电，但正常供电时由反馈维持状态，不需要周期性刷新 电容电荷会泄漏，需要周期性刷新
功耗特点 没有刷新开销，但有漏电和读写开销 有刷新、行激活、读写及接口传输等开销
断电后数据 丢失 丢失

表中的“容量较小/较大”指常见用途下的容量规模；若比较单个 bit 的电路面积，通常恰好是 SRAM 更大、DRAM 更小。功耗则必须结合容量、工艺、工作频率和访问负载判断，不能直接写成“SRAM 一定低、DRAM 一定高”。SRAM 的能耗模型同样需要计入漏电。参见 eCACTI 能耗建模报告。

从一个 bit 看电路

左侧是 SRAM 的 6T 单元，中间是 DRAM 的 1T1C 单元，右侧展示单元组成阵列后的行列选择关系。

SRAM 靠反馈“记住”状态。 典型 6T 单元中，4 个晶体管组成两个交叉连接的反相器，另外 2 个晶体管控制读写访问。反相器会把输入的 0 变成 1、把 1 变成 0；两个反相器首尾相连后，可以稳定在“一端为 0，另一端为 1”的状态。只要供电正常，这个状态就能自行维持，无须定时重写。其具体结构可对照汉堡大学的 6T SRAM 电路说明。

这张 SR 锁存器图用于理解“交叉反馈保持状态”。图中 Q、Q′ 处的接地符号有误，两者应是互补输出，不能都接地；实际 6T SRAM 连接以上一图为准。DRAM 的存储单元采用电容，不是这个锁存器。

DRAM 靠电容“暂存”状态。 可以把电容想成一个会缓慢漏水的小容器：不同电荷状态表示 0 或 1，访问晶体管则像控制出入口的开关。它由此需要两种维护：

  1. 定期刷新：即使无人访问，电荷也会随时间泄漏，必须在状态不可辨认前重新恢复。
  2. 读取后恢复：读取会扰动电容中的电荷，感应放大器需要把微弱信号放大，并恢复单元中的数据。这个过程由芯片内部完成，程序无须为每次读取再发一条写命令。

刷新和读取后恢复都源于电容存储机制，但触发原因不同。可参见 Georgia Tech 的 Memory Systems 讲义。

为什么缓存用 SRAM，主内存用 DRAM

这是一条从电路到系统的取舍链：

  • SRAM 用更多器件换取快速访问。 它不需要 DRAM 式的周期刷新与电荷恢复，适合容量较小、频繁访问、对延迟敏感的缓存。
  • DRAM 用更紧凑的单元换取容量。 单元面积小、密度高，能以较低的单位容量成本容纳大量程序和数据，适合主内存。
  • 系统把两者组合起来。 常用数据尽量由 SRAM 缓存提供，缓存未命中时再访问 DRAM，从而兼顾速度和容量。

因此，DRAM 较慢不只是因为“要刷新”；感知电荷、打开或切换行以及片外传输也需要时间。实际 CPU 缓存与主内存的延迟差距，还包含容量、布线和接口距离的影响。

DRAM 如何组成主内存

常见 DDR 内存属于 SDRAM（Synchronous DRAM，同步动态随机存取存储器）：它按照时钟协调命令和数据传输。这里的 S 是 Synchronous（同步），不要与 SRAM 的 Static（静态） 混淆。

从内存条到存储单元

层次或术语 含义
Channel（通道） 内存控制器与内存之间的一组通信接口；能连接多少内存条取决于平台
DIMM（内存模块） 通常所说的内存条，上面包含多个 DRAM 颗粒及相关电路
Rank（秩） 一组被共同选中、并行提供数据位宽的 DRAM 颗粒；不等同于内存条的一面
Chip（颗粒） 内存条上的 DRAM 芯片；x4、x8、x16 表示单颗粒的数据接口位宽
Bank（存储体） 芯片内可相对独立地进行行操作的部分；按行、列组织数据
Row / Column（行 / 列） 先激活一行，再选择该行中的目标数据；行列数量取决于具体器件
Cell（存储单元） 典型 DRAM 中由 1T1C 保存 1 bit 的物理单元
Row Buffer（行缓冲区） 保存当前打开行的数据，实际由一组感应放大器等电路实现

从左上角沿放大关系阅读：通道连接内存模块，颗粒内有多个 Bank，Bank 内再划分子阵列，最底层才是电容存储单元。

这里每个颗粒提供 16 bit，4 个颗粒共同提供 64 bit。颗粒位宽与单个 Cell 的容量是两个概念。

另一种组合是 8 个 x8 颗粒：它们接收共同的命令和地址，各自提供 8 bit，合计 64 bit，即每个数据传输拍提供 8 Byte。以上均未计入 ECC 校验位。

64 bit 是这里的数据总线位宽，不是内存带宽。 带宽还取决于每秒传输多少次；一次完整的读请求也可能包含多个数据传输拍。

多 Bank 与 Bank Group

各个 Bank 有自己的行缓冲状态。图中的 4～8 个 Bank、16K 行和 1024 列是特定组织示例，不是所有 DRAM 的固定参数；“每列 4～16 bit”也不代表单个 Cell 保存多个 bit。

多 Bank 让内部操作可以重叠。 一个 Bank 传输数据时，另一个 Bank 可以准备下一行。不过，共享同一组数据引脚的 Bank 仍需轮流占用外部总线，不能把内部并行直接理解为总线同时输出多份数据。

DDR4 的 x4/x8 器件通常有 4 个 Bank Group，每组 4 个 Bank；x16 器件通常有 2 组，每组 4 个 Bank。

Bank Group 是在多个 Bank 之上的分组。DDR4 对同组与跨组的连续访问规定了不同时间间隔，控制器可以交错访问不同组，更连续地利用总线。它不表示每个时钟周期都能向外输出 4 份独立数据。 颗粒位宽、Bank 数和分组关系可对照 Micron 的 DDR4/DDR5 对比表。

一次 DRAM 读取经历什么

控制器与地址映射

内存控制器把处理器请求翻译成 DRAM 命令。 它选择通道、Rank、Bank 和行列地址，安排访问顺序，并处理刷新、总线占用和时序约束。将控制器集成进 CPU 可以缩短访问路径，减少经由外部北桥转发的开销。

这是图中所注明的 8 GB DDR3 DIMM 地址映射示例。不同平台可能采用不同位划分或地址交织，不能把这张图当成通用映射规则。

从左向右看，请求经过地址译码后定位到 Bank 和行，再由感应放大器读出数据。右侧进一步放大到晶体管、电容和位线；其中扰码、重映射和耦合效应属于更细的实现问题。

激活、读写与预充电

把一个 Bank 想成有许多抽屉的文件柜，行缓冲区就是当前打开的抽屉。以初始没有打开行的情况为例：

  1. ACTIVATE（激活）：选择一行，感知并放大其中的数据，建立行缓冲内容，同时恢复存储单元的电荷。
  2. READ / WRITE（读 / 写）：给出列地址，对已经打开的行进行读写；一次命令通常以突发方式传输多个数据拍。
  3. PRECHARGE（预充电）：需要换行时，在满足恢复等时间要求后关闭当前行，让位线回到准备状态，随后才能激活同一 Bank 的另一行。

图示概括了“打开行 → 访问 → 关闭行”。其中把存回阵列写在预充电阶段是一种简化：读取后的电荷恢复已在激活过程中进行，不能理解为一直等到 PRECHARGE 才开始恢复。

由此可以区分三种访问情况：

当前 Bank 的状态 访问目标行需要的主要步骤
目标行已经打开：行命中 直接发 READ / WRITE
没有行打开 ACTIVATE → READ / WRITE
打开的是另一行：行冲突 PRECHARGE → ACTIVATE → READ / WRITE

连续访问同一已打开行通常更省时间；反复切换同一 Bank 的不同行则会增加开关行开销。 控制器可以在满足正确性、时序和公平性要求的前提下重排请求，提高行命中率。这也解释了为什么“随机寻址”并不意味着每次访问一样快。相关机制与调度取舍见 Stall-Time Fair Memory Access Scheduling（MICRO 2007）。

扩展：地址翻译也会改变行冲突

这张图来自 Utopia（MICRO 2023）图 8。纵轴以 Radix 页表方案为 1，越低表示行冲突越少；ECH 是一种哈希页表方案，P-TLB 是地址翻译总能命中缓存的理想情况。

读图时关注因果关系即可：地址翻译本身也会发出访存请求，因此翻译方案会影响 DRAM 行冲突。图中的结果属于论文所用负载和配置，不是 SRAM 与 DRAM 的速度对比。

DDR 怎样连续传输数据

突发、预取与流水线

突发（Burst）指一条读写命令带来连续多个数据传输拍，拍数称为 BL（Burst Length，突发长度）。以 64 bit 数据通道和 BL8 为例：

64 bit ÷ 8 × 8 拍 = 64 Byte

因此，一次 BL8 突发可以传完一条 64 Byte 缓存行；这不是 CPU 连发 8 条独立的 READ 命令。处理器按字节寻址、缓存按缓存行填充、总线按拍传输，三者的粒度不同，也不能仅凭总线位宽解释所有数据对齐规则。

预取（Prefetch）则是 DRAM 内部先并行取出较宽的一组数据，再经外部接口依次传出。这里的“预取”是芯片内部组织方式，区别于 CPU 预测未来访存的硬件预取器。

概念 关注的问题
n 倍预取 内部一次准备多少个外部数据拍所需的数据
突发长度 BL 一条命令在接口上连续传输多少拍
DDR 双沿传输 数据接口在时钟上升沿和下降沿都传输数据
请求流水线 在前一个请求完成前，按时序约束继续安排后续请求

图中对比单次请求和流水化发出多个请求。它说明请求可以重叠等待，不是精确的 DDR 波形，也不是单次突发长度的定义。

从 DDR 到 DDR5

类型 典型预取组织
DDR 2n
DDR2 4n
DDR3 8n
DDR4 8n
DDR5 16n

提高传输率，并不要求存储阵列以同样比例提速。 更宽的预取、更快的接口和 Bank 并行共同提高吞吐；DDR4 与 DDR3 都采用 8n 预取，也说明预取倍数并非每代都翻倍。

这张旧表适合观察技术演进，不适合直接查规格。DDR4 的内部速率与 8n 预取、外部速率没有对应起来，带宽上限也有误：按单个 64 bit 数据通道计算，DDR3-1600 是 12.8 GB/s，DDR4-3200 是 25.6 GB/s。

例如图中的 DDR-200、DDR2-400、DDR3-800 都用 100 MHz 的阵列速率作对照，通过 2n、4n、8n 预取对应不同外部传输率。MHz 表示时钟频率，MT/s 表示每秒百万次传输，二者不能混写。

DDR5 进一步把常见 DIMM 的数据接口分为两个独立的 32 bit 子通道。每个子通道使用 BL16，一次仍可传输：

32 bit ÷ 8 × 16 拍 = 64 Byte

所以，DDR5 的 16n 预取不要求 CPU 缓存行变成 128 Byte。对具有外部 ECC 的相应模块，每个子通道还可带有额外校验位；计算有效载荷时仍使用 32 bit 数据位宽。参见 Micron 的 DDR5 模块说明。

怎样读懂访存时序

内存标注中的 CL-tRCD-tRP-tRAS 描述不同阶段的等待要求。读懂它们，需要把“发命令”和“数据真正到达”分开：

参数 含义
CL / tCL（CAS Latency） CAS 是列地址选通的历史名称；CL 描述读命令被接受到首个数据输出的列访问延迟，通常以时钟周期数标注，完整读延迟还需考虑器件配置
tRCD（行到列延迟） ACTIVATE 到可发 READ / WRITE 命令的最小间隔
tRP（预充电时间） PRECHARGE 到同一 Bank 可再次 ACTIVATE 的最小间隔
tRAS（行最短激活时间） ACTIVATE 到允许 PRECHARGE 的最小间隔；不简单等于 tRCD + tCL
tWR（写恢复时间） 最后一个写数据完成后，到允许开始预充电所需的恢复时间
tCCD（列命令间隔） 连续列访问命令之间的最小间隔；DDR4 同组与跨 Bank Group 对应不同约束
CR（命令速率） 常见的 1T/2T 等命令时序设置，涉及命令/地址的建立与采样；不表示选择 Bank 后固定多等一次

先发送 ACT 和行地址，再发送读命令和列地址；等待之后，数据才出现在 DQ 数据线上，DQS 为配套的数据选通信号。

这张图展示的是不同 Bank Group 的连续 READ，两次命令间遵守 tCCD_S，而非“同一行两次访问”。图中的 tRPRE、tRPST 分别是读数据选通信号的前导和后导时间。

如果只把 CL 周期数换算成时间，可使用：

列访问延迟（ns）= CL × 2000 ÷ 数据传输率（MT/s）

例如 DDR4-3200、CL16 对应 16 × 2000 ÷ 3200 = 10 ns。这只是列访问阶段的时间，不是 CPU 一次完整的内存访问延迟；遇到未打开的行或行冲突，还要考虑激活、预充电、控制器排队等开销。更高带宽也不等于单次访问延迟同比下降。时序定义可对照 Micron DDR4 数据手册。

扩展：传输校验

CRC（循环冗余校验）让发送端计算校验码，接收端重新计算并比较，以检测传输错误。图中是控制器向 DRAM 发送数据的方向。CRC 本身不负责纠错，也不能与保护存储数据的 ECC（纠错码）混为一谈。
