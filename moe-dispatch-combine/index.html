THE IDEA / 原理速读

两次跨 rank 通信，夹着一次专家计算

01

路由决定副本

Router 为每个 token 选出 Top-k 个专家。Top-2 时，一个 token 会对应两条专家任务；图中的两条线是两份逻辑副本，不是两个新 token。

02

Dispatch 改变布局

副本带着来源位置和专家编号，到专家所在 rank 汇集。专家按接收到的任务处理；负载不均时，某些专家会收到更多 token。

03

Combine 回原槽位

每份专家结果返回 token 的原 rank，再用路由权重加权求和：y[t] = Σ w[t,e] · Fₑ(x[t])。输出仍排在原来的 token 槽位。

SCOPE / 来源与边界

这是一张可操作的原理图

交互数据是为讲解而设的确定性小例子：x[0] 是 token 向量的首元素示意值；动画中的专家函数 Fₑ(x[0]) = x[0] + 4(e+1) 只是让合成过程能手算，不代表真实 FFN。载荷估算只计 token 向量，不含权重、索引、对齐、元数据或协议开销。

图中“到达”和阶段顺序是教学状态，不代表真实网络完成、硬件同步或性能数据。真实实现的打包、缓存、同步、返回顺序与本图可能不同。
